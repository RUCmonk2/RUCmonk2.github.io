## 输入是一段文字，读取要把它转换成目标类型

键盘输入的 `12` 起初是字符。`std::cin >> value` 按变量类型尝试解析它，成功后才把数值存入变量。换行通常只是格式化整数提取时的分隔空白，不表示只能一行读一个数。

| 写法 | 含义 | 名称与约定 |
| --- | --- | --- |
| `std::cin` | 标准输入流 | cin 是标准库规定的名字，常按 character input 理解 |
| `>>` | 流提取运算 | 此处从流读取；用于内置整数时也可能表示右移 |
| `a,b` | 用于接收两个整数的变量 | 只是自选名字；类型决定提取规则 |
| `if (std::cin >> a >> b)` | 检查整段提取是否保持可用状态 | 这是为练习补充的成功检查；输入后还要看流状态 |

## 完整程序

```cpp
#include <iostream>
int main() {
    int a = 0, b = 0;
    if (std::cin >> a >> b) {
        std::cout << a << ' ' << b << '\n';
    }
    return 0;
}
```

输入 `12 34`，输出 `12 34`。把两项输入分成两行，通常得到相同结果：默认格式化整数提取跳过前导空白，读取一个整数后继续读取下一个。

## 按顺序追踪失败

输入 `12 x` 时，第一项可转换为整数 12，第二项不能按预期读取整数。流进入失败状态，条件不成立，因此本例不输出那一行。变量都初始化为零，并不等于第二次读取成功；检查流状态正是为了分开这两件事。

这里没有实现输入错误后的恢复循环。恢复需要理解失败标志与未消费字符，不能只重复同一句提取就期待错误自动消失。

## 自己试试

1. 输入前增加几个空格，或把两个整数分两行，结果是否必然改变？
2. 输入 `7 q`，本例会打印 `7 0` 吗？

<!-- solutions -->
1. 默认格式化整数读取会跳过前导空白，所以这些分隔变化不改变两项数值。
2. 不会进入输出分支，因为第二项提取失败；不能把零初始化当作读取成功的证据。

## 格式化输入、链式提取与状态

标准输入流 `std::cin` 的整数提取是格式化输入操作，默认跳过前导空白，并按流设置和数值转换规则读取数据。`operator>>` 返回流引用，允许连续提取；每个提取仍按顺序影响流状态和目标对象。

格式错误或超出可表示范围可能设置 `failbit`，底层输入错误可能设置 `badbit`，到达输入末尾还涉及 `eofbit`。流在条件上下文中的布尔转换用于检查失败状态，不能简单解释成“文件没有到末尾”。合法末项刚好在末尾结束时，提取仍可能成功。

成功读完两个整数只说明所要求的两项解析成功，不代表整行没有多余字符。需要严格整行验证时还需额外规则。本节点在 L02 基本提取之上补充状态检查，帮助读者避免初始化默认值掩盖失败输入。
