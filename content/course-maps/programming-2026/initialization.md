## 在第一次读取之前，给出一个确定的起点

写下变量类型和名字，不一定已经给它一个可以安全读取的值。本节用显式初始化消除这种含糊；不要靠“这次运行好像是零”来判断语言规则。

| 写法 | 含义 | 区别 |
| --- | --- | --- |
| `int count = 0;` | 定义时初始化为零 | 程序清楚地指定第一次读取的值 |
| `int count{};` | 此处将整数值初始化为零 | 花括号也是初始化语法，不是空语句 |
| `int count;` | 未写初始化器的局部整数定义 | 普通块内自动变量不会因此自动保证为零 |
| `count = 3;` | 给已经存在的对象赋值 | 必须在读取前确实执行到这一步 |

## 可安全运行的例子

```cpp
#include <iostream>
int main() {
    int count = 0;
    int next = count + 1;
    std::cout << count << ' ' << next << '\n';
    return 0;
}
```

输出 `0 1`。先确定 `count` 为 0，才用它算 `next`。如果把第一行改为没有初始化器，却仍立即计算 `count + 1`，就不能再为这个普通局部整数读取给出可靠输出。

## 为什么不演示“随机打印一个垃圾数”

在这里读取不确定的局部 `int` 值会导致未定义行为，不能承诺它只是打印某个随机数。程序可能在不同优化或编译器下表现不同。公开示例中的反例用于辨认问题；正常练习使用初始化后的代码。

## C++17 的标量初始化规则

对块内普通自动存储期的 `int` 对象，`int x;` 执行默认初始化而不进行值初始化，其值不确定。对这类不确定 `int` 值实施读取所需的左值到右值转换通常导致未定义行为。某些字符类型情形存在特别规则，不能把它们推广到本例整数。

`int x = 0;` 指定初始化表达式；`int x{};` 在此处使整数成为零。静态存储期对象另有零初始化阶段，不能用全局变量观察到的零值反推自动局部变量的规则。

赋值可以在首次读取前建立确定值，但必须检查所有控制流路径，包括输入失败时是否仍继续读取。初始化为零不表示输入一定成功，也不会自动修复流的失败状态。该节点按 C++17 说明，避免混用后续标准版本对不确定值的新增术语。
