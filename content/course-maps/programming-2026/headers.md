## 让编译器知道一个名字指什么

写 `std::cout` 前，要让编译器看见它的声明。头文件提供标准库接口，命名空间则帮助区分名字。这两件事不能互相替代。

| 写法 | 含义 | 名称与约定 |
| --- | --- | --- |
| `#include <iostream>` | 引入标准流接口声明 | iostream 来自 input/output stream |
| `std` | C++ 标准库使用的命名空间 | 来自 standard，不能随意拼错 |
| `::` | 作用域解析运算符 | `std::cout` 指明从哪里查找 `cout` |
| `using namespace std;` | 在名称查找中考虑该命名空间 | 不是“把标准库加载进内存”的运行命令 |

## 完整代码与输出

```cpp
#include <iostream>
int main() {
    std::cout << "Welcome!\n";
    return 0;
}
```

输出一行 `Welcome!`。这里没有写 `using namespace std;`，因为已经使用限定名 `std::cout`。课件也展示过先写 using 指令，再使用短名 `cout`；两种写法都需要相应的头文件。

## 逐项尝试，而不是一次删掉两行

先保留头文件，只把 `std::cout` 改成 `cout`：本例没有 using 声明，短名将无法按此上下文找到。再恢复 `std::cout`，单独删掉头文件：不能依靠偶然的编译环境预先提供声明。一次只改一个因素，才能知道报错来自缺少声明还是名称查找。

## 声明可见性与限定名称查找

预处理指令 `#include` 按规定把指定头的内容提供给翻译单元。标准头 `<iostream>` 提供标准流对象等接口；程序应包含所使用设施的相应头，而非依赖其他头偶然间接包含它。

`std::cout` 是限定名，`::` 指定命名空间范围。using-directive 影响未限定名称查找，不复制库定义，也不执行运行时加载。局部名字和多个命名空间中的同名实体可能产生遮蔽或歧义，因此示例使用显式 `std::` 以便阅读。
