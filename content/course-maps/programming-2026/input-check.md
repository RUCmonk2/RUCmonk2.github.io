## 预测、运行、比较，才形成一个闭环

把输入输出题做成三列：输入文字、程序执行的步骤、精确预期输出。正常输入之外，再加一个失败输入，才能检查程序是否真的区分成功读取和无效数据。

| 写法 | 含义 | 检查重点 |
| --- | --- | --- |
| `int value = 0;` | 建立确定初值 | 初值不是用户已经输入成功的证明 |
| `if (...)`、`else` | 根据条件选一个分支 | 花括号明确各分支语句范围 |
| `std::cin >> value` | 尝试读一个整数并检查流 | 同时涉及变量值和流状态 |
| `"invalid\n"` | 明确的失败输出 | 与正常整数输出分开，便于核验 |

## 一段完整的回显程序

```cpp
#include <iostream>
int main() {
    int value = 0;
    if (std::cin >> value) {
        std::cout << value << '\n';
    } else {
        std::cout << "invalid\n";
    }
    return 0;
}
```

这是对 L02 回显示例补充成功检查的版本。`if` 根据条件选择分支；先把它当作“读成功走上面，失败走下面”，后续学习控制流时再系统展开语法。

## 三组具体输入

| 输入 | 预期输出 | 为什么 |
| --- | --- | --- |
| `42` | `42` 后换行 | 正整数可被读取 |
| `-7` | `-7` 后换行 | 负号属于合法整数格式 |
| `hello` | `invalid` 后换行 | 不能从起始文字得到所需整数 |

若输入 `12abc`，整数提取可以先读出 12 并留下 `abc`，所以本例会输出 `12`。它检查的是“这次整数提取成功”，不是“整行只含一个合法整数”。需求不同，需要的检查也不同。

## 输入合同与可观察结果

程序的输入合同决定何谓成功。该回显程序只要求一个格式化 `int` 提取成功；流布尔转换检查失败位，与所读数值的真假无关。因此读取整数零仍可进入成功分支，合法数值后有剩余文本也未必导致本次提取失败。

更严格的“整行一个整数”合同还需要检查未消费字符及行结束；多项输入则需验证每次提取并处理失败后的状态。输入恢复涉及清除状态和消费不合法字符，不能单靠重新初始化接收变量解决。

测试用例应包含正常正数、零、负数及非数字开头，并比较精确输出文本。边界值测试要以所选实现的整数范围为准。样例全部通过只覆盖这些输入，不能证明所有输入正确；但它能直接揭示把数值真假误当流状态等常见错误。
