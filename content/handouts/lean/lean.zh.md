## 1 | 从哪里开始

假设你知道两件事：作业已经交了，老师也签了字。有人要你先出示签字，再出示作业，你手里的两份凭据就够了。第一节实验要证明的正是这个动作。到了插入排序，手里的凭据会变成“已经排好序”和“元素一个也没丢”。我们仍然要弄清楚每份凭据从哪里来，又能用在哪里。

### 先认这几种写法

| 写法 | 读法与约定 |
| --- | --- |
| `n : Nat` | $n$ 是自然数，从 $0$ 开始。`Int` 也允许负数。 |
| `P : Prop` | $P$ 是一个命题；`h : P` 表示手里有 $P$ 的一个证明。 |
| `P → Q` | 给我 $P$ 的证明，我就能构造 $Q$ 的证明。 |
| `P ∧ Q` | 两份证明放在一起，左边证明 $P$，右边证明 $Q$。 |
| `⊢ Q` | 此处待证 $Q$。这一行上面列出可以使用的对象和假设。 |
| `xs : List Nat` | 一个有限自然数列表。全文查找下标从 $0$ 开始。 |
| `acc`, `rest` | 已处理部分的累积值、尚未处理的输入；类型随算法而变。 |

### 怎么安排第一次自学

先读[第 2 至 5 节](#unit-2)，在在线编辑器里亲手把一个正确证明改错，再改回来。[第 6 至 9 节](#unit-6)练习列表归纳与求和。[第 10 至 15 节](#unit-10)用插入排序串起循环、引理与完整规格。[第 16 至 18 节](#unit-16)自行分析查找。接着试着只凭记忆，做[第 19 节](#unit-19)的题，再翻解答。从[第 23 节](#unit-23)起，依第四版题号继续做二进制加法、算法分析、分治和章末四道思考题。

> 手边放一张纸，分成“已知条件”和“当前目标”两列。每遇到一行策略，先改纸上的两列，再看实验室里 Lean 给出的状态。

## 2 | 第一次运行一个文件

打开网站的 Lean 实验室，选“交换合取的顺序”，点“在线运行”。打开的文件里有三个定理。先找到 `theorem swapAnd`，把光标放到 `intro h` 的行末，看信息窗口。同一处也可以在站内点击这行代码查看编译时记录的状态。

### 在文件末尾加四行

```lean
#check (3 : Nat)
#eval (2 + 3 : Nat)
#check (2 + 3 = 5)
example : (2 + 3 : Nat) = 5 := by rfl
```

第一行询问一个表达式的类型，Lean 会告诉你这个数属于 `Nat`。第二行要求实际计算，得到 $5$。第三行检查整个等式的类型，得到 `Prop`。此时你知道“$2+3=5$”写成了一句合法命题。第四行才给这句命题配上证明。`example` 可以声明一个不命名的例子。`rfl` 让两侧按定义计算，并检查得到的结果是否相同。

### 读懂定理的外壳

```lean
theorem addOneEq (a b : Nat) (h : a = b) : a + 1 = b + 1 := by
  rw [h]
```

从左往右读：名字是 `addOneEq`；给定两个自然数 $a,b$；再给定一份 $a=b$ 的证明 $h$；冒号之后写的是你承诺证明的结论。`:=` 引出给这个名字的内容。`by` 表示后面用策略逐步构造证明。证明体向右缩进，定理名和局部假设名区分大小写。

### 观察一次失败

把第四行例子的右边 $5$ 改成 $6$。两侧算出来分别是 $5$ 和 $6$，`rfl` 会在这里失败。改回 $5$，等错误消失。输入逻辑符号时可直接复制代码；在 Lean 编辑器中输入 `\and` 再按空格可得到 $\wedge$。

> 算过一组数，只说明这组数的结果。后面的排序定理带有任意列表参数，证明必须能接住这个参数的每一种取值。

## 3 | 把两份证明调换顺序

设 $P$ 表示“作业已交”，$Q$ 表示“老师已签字”。给你“作业已交且老师已签字”，要写下“老师已签字且作业已交”。这个推理与作业内容无关，所以可以把 $P,Q$ 留作任意命题。

```lean
theorem swapAnd (P Q : Prop) : P ∧ Q → Q ∧ P := by
  intro h
  constructor
  · exact h.right
  · exact h.left
```

### 一步一步改纸上的两列

开始时只有两个命题的名字。光是给一句话起名，手里还没有这句话的证明。此时的目标是整个蕴含式。`intro h` 让我们暂取它的前提成立，并把这份前提命名为 $h$。Lean 的窗口成为

```text
P Q : Prop
h : P ∧ Q
⊢ Q ∧ P
```

接下来想一想：要把一个“且”交给别人，必须把哪两样东西一起交出去？`constructor` 选用合取的构造方式，留下两个目标。两个目标都可以使用 $h$，第一个要 $Q$，第二个要 $P$。`·` 把后面的策略放进其中一个分支。

从 $h$ 的右侧取证据，`h.right` 的类型就是 $Q$。`exact` 检查你交出的项能否满足当前目标，匹配成功就关闭这个分支。第二个分支用 `h.left`，类型为 $P$。两个分支都关掉以后，我们就有了从任意前提 $h$ 构造结论的办法。

> 如果只做到第一条 exact，站内可能显示“当前分支已完成”。这时第二个目标仍待处理。回到 constructor 那一步能看到两个目标的原始顺序。

## 4 | 从类型错误读回数学

在上一节的第一条 `exact` 后写 `h.left`。Lean 错误信息里最值得读的是两行：交来的项具有类型 $P$，当前位置需要类型 $Q$。按纸笔证明翻译，就是老师请你出示签字，你递过去的是作业。哪怕在这个故事中两句话都恰好为真，Lean 也需要你给出所要求的那一份证明。

### 把完整构造压缩成一行

```lean
example (P Q : Prop) (h : P ∧ Q) : Q ∧ P := by
  exact ⟨h.right, h.left⟩
```

这里一对尖括号按结论的顺序装入两个项。第一格的期望类型是 $Q$，第二格是 $P$。上一节用 `constructor` 把这两个空格分别呈现在窗口中；此处把两格同时填完。内核最终检查的是构造出来的证明项的类型。

### 换一个目标，自己挑证据

```lean
example (P Q R : Prop) (h : P ∧ (Q ∧ R)) : R ∧ P := by
  constructor
  · exact h.right.right
  · exact h.left
```

沿着括号读：$h$ 的右半边证明 $Q\wedge R$；从这半边再向右，才拿到 $R$。如果停在 `h.right`，交出去的是一整对，目标只要其中的 $R$。第二个分支只需从最外层向左走一步。

### 手中有一个蕴含式时

若 `f : P → Q` 且 `hp : P`，那么 `f hp` 就是类型为 $Q$ 的项。把空格读作函数应用即可。归纳假设有时也长成一个函数，稍后写 `ih (acc + x)`，道理与此相同。

> 快速自测：在上面的嵌套合取例子里，若把目标换成 $Q$，该拿哪一项？先沿外层向右，再沿内层向左，因此写 exact h.right.left。

## 5 | 替换以后，为什么目标消失了

已知 $a=b$，要证 $a+1=b+1$。在纸上，我们在两个边长相等的线段后各添一单位。写成代数推导，只需把左边的 $a$ 改写成 $b$，再利用每个数等于它自己。

```lean
theorem addOneEq (a b : Nat) (h : a = b) : a + 1 = b + 1 := by
  rw [h]
```

把策略执行前的目标、替换产生的中间式和最后一步分开写：

$$

 a+1=b+1\quad\xrightarrow{\ a\mapsto b\ }\quad b+1=b+1
 \quad\xrightarrow{\text{自反性}}\quad \text{完成}.

$$

`rw [h]` 读取等式 $h$ 的方向，在目标中利用它重写；如果重写后的目标可以用自反性关闭，这个策略会顺手做完。因此最后的状态已经没有目标。中间的 $b+1=b+1$ 是这行内部发生的变化，回放不另停一帧。

### 怎样看出方向写反了

设 `h : b = a`，手中的另一个事实是 `ha : a = 3`，目标是 `b = 3`。这次可以先把目标中的 $b$ 改成 $a$，再交出 `ha`。若拿到的等式写作 `h : a = b`，就用反方向。

```lean
example (a b : Nat) (h : a = b) (ha : a = 3) : b = 3 := by
  rw [← h]
  exact ha
```

### 三种很像的动作

`rfl` 检查两侧是否能按定义化成同一表达式。`change` 把当前目标写成按定义等价的另一种样子，方便观察。`rw` 使用一条具体等式替换。接下来列表拼接的证明中，先用 `change` 看清结构，再用 `rw` 引入一个已经证明的事实。

> 尝试把上例的 h 删除。代入的依据也随之消失。检查错误时先找清楚“我想替换哪一项”和“用的是哪条等式”。

## 6 | 为什么要沿着表头和表尾拆

`List Nat` 表示自然数列表。它只有两种生成方式：空列表 `[]`，或者在已有列表 `rest` 的前面放进一个元素 `x`，写作 `x :: rest`。例如 `[4, 2]` 可以展开为 `4 :: (2 :: [])`。列表有顺序，也允许重复值。

### 拼接的定义给了两条计算规则

令 $A,B$ 为列表，$x$ 为单个元素。把 `++` 读成“把右边列表接到左边的末尾”。计算时对左边列表分情况：

$$

 []\mathbin{++}B=B,\qquad (x::A)\mathbin{++}B=x::(A\mathbin{++}B).

$$

这里 $++$ 在公式中表示一个二元运算符。第一条可以立刻返回右边。第二条先把左边的表头放回输出，把剩下的拼接工作交给较短的尾部。

$$

\begin{aligned}
 [4,2]\mathbin{++}[] &= 4::([2]\mathbin{++}[])\\
 &=4::(2::([]\mathbin{++}[]))\\
 &=4::(2::[])=[4,2].
\end{aligned}

$$

### 把数字擦掉会怎样

具体列表能一直算到底。当输入只叫 `xs` 时，你不知道它有没有表头。计算到 `xs ++ []` 就遇到了这个问题。反过来，`[] ++ xs` 的左边已知是空表，第一条规则立即生效。两道看起来对称的题，适合的证明方法不同。

```lean
example (xs : List Nat) : [] ++ xs = xs := by
  rfl
```

> 思考：若有人说“所有列表都非空，因为可以取出它们的第一项”，漏掉了哪一种构造？在归纳证明中，Lean 会明确列出空列表分支，必须单独处理。

## 7 | 写出第一份完整的归纳证明

我们要证明任意自然数列表 $L$ 满足 $S(L): L\mathbin{++}[]=L$。纸笔证明只需两件事：证明 $S([])$；在假设 $S(R)$ 的情况下证明 $S(x::R)$。任意有限列表都能从空表逐次接上表头得到，这两件事覆盖了每一个列表。

```lean
theorem appendNil (xs : List Nat) : xs ++ [] = xs := by
  induction xs with
  | nil => rfl
  | cons x rest ih =>
    change x :: (rest ++ []) = x :: rest
    rw [ih]
```

### 空表分支与递推分支各欠什么

`induction xs with` 指定沿列表的构造做归纳。`nil` 分支的目标是 `[] ++ [] = []`。左边按定义化简成右边，`rfl` 关闭分支。`cons` 分支拿到了一个元素 $x$、一个更短的列表 `rest`，以及关于这个更短列表的证据 `ih`。

```text
ih : rest ++ [] = rest
⊢ (x :: rest) ++ [] = x :: rest
```

先展开一次拼接，左边成为 `x :: (rest ++ [])`。`change` 让双方共有的表头显出来。然后 `rw [ih]` 只替换尾部，左右均为 `x :: rest`。

### 为什么没有循环论证

以输入 $[4,2]$ 为例，证明 $S([4,2])$ 时可以调用 $S([2])$；后者只需要 $S([])$，而 $S([])$ 已经独立证明。任何这样的调用链每次都缩短一个元素，最终停在空表。

> 合上代码，重写三行纸笔推理。第一行写归纳假设的准确对象，第二行只展开一次定义，第三行圈出能被 ih 替换的子式。

## 8 | 手算一次带累加器的循环

现在把一个整数列表从左扫到右。用 `acc` 保存手头的和，拿走表头 $x$ 后把它更新为 `acc + x`。空表返回 `acc`。这是书中数组循环的列表模型，累加值的类型用 `Int`，可以处理负数。

```lean
def sumFrom (acc : Int) : List Int → Int
  | [] => acc
  | x :: xs => sumFrom (acc + x) xs
```

### 一笔总账，分在两个地方

从 `acc = 5`、剩余输入 $[3,-2,4]$ 开始。每次把一项从待处理清单移到账上。试着先遮住最后两列，自行填表。

| 轮次 | 剩余列表 | 手头的数 | 剩余之和 | 两者相加 |
| --- | --- | --- | --- | --- |
| 0 | $[3,-2,4]$ | 5 | 5 | 10 |
| 1 | $[-2,4]$ | 8 | 2 | 10 |
| 2 | $[4]$ | 6 | 4 | 10 |
| 3 | $[]$ | 10 | 0 | 10 |

第三列不断改变，最后一列始终为 $10$。原因是更新前的总量 $a+(x+s)$ 等于更新后的 $(a+x)+s$。这里 $s$ 表示尾部的和，唯一用到的代数规则是加法结合律。

### 为什么把初值也写进定理

最终使用的函数从 $0$ 开始，但做完一次更新，下一次调用已经从 $0+x$ 开始。如果手中只有“从 $0$ 开始时是正确的”这一句话，便无法直接套在更新后的调用上。我们把结论加强为

$$

 \mathrm{sumFrom}(a,L)=a+\mathrm{sum}(L)\qquad \text{对每个整数 }a.

$$

取 $a=0$ 就能取回原问题。先证明更强的命题，还让程序里每一个中间状态都有了同一条解释。

> 把输入换为空表、初值换成 $-7$。函数返回多少？最后一列的写法应当仍成立。

## 9 | 累加器改变时，怎样使用归纳假设

```lean
theorem sumFrom_correct (acc : Int) (xs : List Int) :
    sumFrom acc xs = acc + xs.sum := by
  induction xs generalizing acc with
  | nil => simp [sumFrom, List.sum_nil, Int.add_zero]
  | cons x xs ih =>
    change sumFrom (acc + x) xs = acc + (x + xs.sum)
    rw [ih (acc + x)]
    exact Int.add_assoc acc x xs.sum
```

`generalizing acc` 保证在证明较短列表时仍然可以任选初值。把 `ih` 想象成一张写着空格的收据：“如果初值填 $b$，在尾部 `xs` 上运行的结果就是 $b+\mathrm{sum}(xs)$。”这里必须填 $b=a+x$，因为程序下一次调用实际传入的就是这个值。

### 把每一行策略翻译成等式

设 $s=\mathrm{sum}(xs)$。空表时目标化为 $a=a+0$，`simp` 按所列规则计算并消去右边的零。非空时只看左侧计算过程：

$$

\begin{aligned}
\mathrm{sumFrom}(a,x::xs)
 &=\mathrm{sumFrom}(a+x,xs) &&\text{展开一次程序}\\
 &=(a+x)+s &&\text{用归纳假设，填入 }a+x\\
 &=a+(x+s) &&\text{加法结合律}\\
 &=a+\mathrm{sum}(x::xs) &&\text{表头加尾和}.
\end{aligned}

$$

源码的 `change` 同时展开左右两端的定义。`rw` 完成第二行。`Int.add_assoc` 接受三个整数，产出的等式方向恰好与剩余目标一致。最后令初值为零，再用 $0+t=t$，就得到 `sumList_correct`。

> 回到上一节的第 1 轮。此时该向归纳假设传入 $5$、$3$ 还是 $8$？把数字换回变量，你就能自己写出 rw 的参数。

## 10 | 先看算法的两层递归

一手拿着已经排好的牌，另一手拿着还没看的牌。外层每次取一张新牌，内层在已排部分中给它找一个位置。我们用自然数列表模拟这两叠牌，升序时比较规则取 $x\le y$。

```lean
def insert (x : Nat) : List Nat → List Nat
  | [] => [x]
  | y :: ys => if r x y then x :: y :: ys else y :: insert x ys
```

这里 `r` 和它的可判定性在文件上方声明。`r x y` 的意思是“$x$ 可以排在 $y$ 前面”。在升序下，把 $2$ 插入 $[1,4,5]$：遇到 $1$，$2\le1$ 为假，保留 $1$ 并递归；遇到 $4$，$2\le4$ 成立，返回 $[2,4,5]$；回到上一层，得到 $[1,2,4,5]$。

### 外层到底在哪一刻维持有序

| 刚插入 | 已排部分 `acc` | 剩余 `rest` |
| --- | --- | --- |
| 初始 | $[]$ | $[4,2,5,2,1]$ |
| 4 | $[4]$ | $[2,5,2,1]$ |
| 2 | $[2,4]$ | $[5,2,1]$ |
| 5 | $[2,4,5]$ | $[2,1]$ |
| 2 | $[2,2,4,5]$ | $[1]$ |
| 1 | $[1,2,2,4,5]$ | $[]$ |

每一行的已排部分都有序，但剩余输入可以杂乱。内层每次缩短待比较的已排列表；外层每次缩短未处理列表。两层各自都有一个会变空的参数。这解释了为什么递归可以停，也提示我们应该对哪一个列表做归纳。

> 去“插入排序 · 保持有序”，展开 2.1-1 的走查。遮住下一行，只说出本次比较停在哪个元素前面。这个练习的输入是实验室自选的。

## 11 | 一个排序函数要交出两份证明

把 `Pairwise r ys` 展成一句话：对 `ys` 中任意两个位置 $i<j$，排在前面的值与后面的值满足关系 $r$。升序时就是 $ys_i\le ys_j$。空列表没有这样的两个位置，单元素列表也没有，两者都满足条件。

另一半用 `List.Perm` 表示“是一个排列”。例如 $[2,4,2]$ 与 $[4,2,2]$ 互为排列，因为可以移动元素得到另一列；$[2,4]$ 与 $[4,2,2]$ 包含相同的不同取值，却差了一个 $2$。

### 用两个坏算法检查规格写得够不够

函数一丢弃全部输入，一律返回 $[]$。它每次都给出有序结果。在输入 $[7]$ 上检查排列条件，它就无法通过。函数二原样返回输入，它总能通过排列检查，但输入 $[3,1]$ 时违反有序性。把两条要求合在一起，才抓住排序要做的事。

$$

 \underbrace{\mathrm{Pairwise}(r,\mathrm{out})}_{\text{检查顺序}}
 \quad\land\quad
 \underbrace{\mathrm{Perm}(\mathrm{out},\mathrm{in})}_{\text{检查元素及次数}}.

$$

箭头从已知引理指向调用它的证明。横向的箭头很重要：为了证明一次插入后仍有序，我们需要辨认插入后的某个元素从哪里来。排列引理可以告诉我们，它要么是新值，要么来自旧列表。

## 12 | 一次插入怎样保住重复次数

固定待插入的 $x$，目标是 `(insert r x ys).Perm (x :: ys)`。右边把新牌直接放在最前面，给出了一个容易核对的参照。只要左边能由右边调换位置得到，就知道没有丢牌或多造牌。

### 把一个具体交换拆开

将 $4$ 插入 $[2,5]$ 会得到 $[2,4,5]$。参照是 $[4,2,5]$。先看尾部，把 $4$ 插入 $[5]$ 得到 $[4,5]$，已经等于尾部的参照。在两边都加回 $2$，得到 $[2,4,5]$；最后交换前两项，就到达整列的参照 $[4,2,5]$。

### 读原证明的三个分支

```lean
  induction ys with
  | nil => exact .refl _
  | cons y ys ih =>
    by_cases h : r x y
    · rw [insert, if_pos h]
    · rw [insert, if_neg h]
      exact (List.Perm.cons y ih).trans (.swap x y ys)
```

空表时两边都是 $[x]$，`Perm.refl` 给出“自己是自己的排列”。非空时用比较结果分两支，`h` 在第一支证明 `r x y`，在第二支证明其否定。`if_pos` 和 `if_neg` 据此选中程序实际执行的分支。

比较成立时，输出本来就是 $x::y::ys$。比较失败时，输出形如 $y::\mathrm{insert}(x,ys)$。归纳假设 `ih` 说后面的插入结果与 $x::ys$ 互为排列。`Perm.cons y ih` 允许两边同时加上 $y$；`.swap` 交换两个相邻表头；`.trans` 把两段排列证明首尾接起来。

> 在纸上把“同时加表头”和“交换两个表头”各画一个箭头。只证明每个元素都出现过，会遗漏什么？试着拿含有两个 $2$ 的输入来反驳。

## 13 | 从一次比较推出整列有序

假设 $y::ys$ 已经有序。把这个假设拆开，可以拿到两件事：$y$ 排在尾部每个元素 $z$ 前面，满足 $r(y,z)$；尾部 `ys` 自身也有序。在代码中 `List.pairwise_cons.mp hs` 取出这两件事，分别命名为 `hy` 和 `hys`。

### 情形一：新值可以放在表头

若 $r(x,y)$，输出就是 $x::y::ys$。旧的后半列仍有序。新增的任务只有“$x$ 能放在后面每个值之前”。遇到 $y$ 本身，刚才那次比较给出了证明；遇到 `ys` 中的 $z$，由 $r(x,y)$、$r(y,z)$ 和传递性推出 $r(x,z)$。因此比较表头一次就足够。

```lean
rw [insert, if_pos hxy, List.pairwise_cons]
refine ⟨?_, hs⟩
```

尖括号的第二格已经填入旧列的有序性 `hs`。`?_` 留下第一格，要求我们逐个说明新表头与后面元素的关系。

### 情形二：保留原来的表头

若 $r(x,y)$ 为假，程序保留 $y$，在尾部递归插入 $x$。对较短列表使用归纳假设，可知新尾部有序。还需要验证 $y$ 能放在新尾部的每个 $z$ 前面。上一节的排列引理保证 $z$ 的来历只有两种：

- 如果 $z=x$，全可比性给出 $r(x,y)\lor r(y,x)$。前一项已被排除，所以 $r(y,x)$ 成立。
- 如果 $z$ 是旧尾部元素，原先的 `hy` 就给出 $r(y,z)$。

以 $x=4$、旧列 $[2,5]$ 为例，新尾部是 $[4,5]$。$2\le4$ 来自比较失配后的反向关系；$2\le5$ 来自原列表有序。两种依据各用一次。

> 现在可以给关系 r 写出三个接口要求：程序要能判定一次比较；证明需要传递性；比较失败后要能从全可比性选出反向关系。

## 14 | 从一次插入走到任意长度的输入

`sortFrom r acc rest` 从已排部分 `acc` 开始，把 `rest` 中的元素逐个插入。我们要证明：任给有序的 `acc`，处理完 `rest` 所得的列表仍有序。对尚待处理的 `rest` 做归纳，初值 `acc` 仍可任选。

```lean
  induction rest generalizing acc with
  | nil => exact hAcc
  | cons x xs ih =>
    have hStep : (insert r x acc).Pairwise r :=
      insert_ordered r trans total x acc hAcc
    exact ih (insert r x acc) hStep
```

空表分支立即返回 `acc`，手里的 `hAcc` 正好证明它有序。在非空分支，`have` 给一个中间事实起名。调用上一节的引理得到 `hStep` 后，当前目标依旧是最终结果有序。现在把更新后的累积列表和证明 `hStep` 一起交给 `ih`，剩余输入已经缩成 `xs`。

### 另一条归纳线怎样保持全部元素

若用 $\sim$ 表示“互为排列”，令 $a'=\mathrm{insert}(x,a)$。从 $a$ 出发处理 $x::s$ 等于从 $a'$ 出发处理 $s$。后者的结果按归纳假设与 $a'\mathbin{++}s$ 互为排列。一次插入的排列引理又告诉我们

$$

 a'\mathbin{++}s\ \sim\ (x::a)\mathbin{++}s\
 \sim\ a\mathbin{++}(x::s).

$$

第一步在一对排列的右边接上相同尾部；第二步让 $x$ 越过整段 $a$。源码用 `append_right` 和 `perm_middle` 的反向证明完成这两步。

### 回到最外层的入口

```lean
  constructor
  · exact sortFrom_ordered r trans total xs [] .nil
  · exact sortFrom_perm r xs []
```

令初始累积列表为 $[]$。空表有序的证明是 `.nil`；空表拼上 `xs` 按定义就是 `xs`。两条子目标分别关闭，这就证明函数式插入排序对任意自然数列表满足完整规格。

## 15 | 改为降序，哪些证明要重做

把关系 $r(x,y)$ 定义为 $y\le x$。例如处理 $[2,5,2]$，第一次插入得到 $[2]$，第二次比较“$2\le5$？”成立，把 $5$ 放在前面。第三次遇到表头 $5$ 时测试“$5\le2$？”失败，于是继续比较尾部。最终 $[5,2,2]$ 有序，原来的两个 $2$ 都在。

### 将一般定理用到一个具体关系

源码中 `fun x y => y ≤ x` 就是这个二元关系。目标仍由合取组成：按反向关系有序，而且结果与输入互为排列。`apply insertionSort_correct` 把一般定理的结论对准当前目标。Lean 已经从目标推断出关系和列表，剩余两个条件要我们填写。

```lean
  apply insertionSort_correct
  · intro x y z hyx hzy
    exact Nat.le_trans hzy hyx
  · intro x y
    exact Nat.le_total y x
```

第一支要证明传递性。把一般关系的公式

$$

 r(x,y)\ \longrightarrow\ r(y,z)\ \longrightarrow\ r(x,z)

$$

逐项换成自然数关系，就得到“若 $y\le x$ 且 $z\le y$，则 $z\le x$”。为了让不等式的中间项接起来，先递给 `Nat.le_trans` 的应是 $z\le y$，再给 $y\le x$。这就是代码里 `hzy hyx` 次序的来历。

第二支要求 $y\le x$ 或 $x\le y$。`Nat.le_total y x` 的输出恰好匹配。一般定理里关于元素排列的证据也随之可用。

> 能把这里的 $\le$ 换成严格小于吗？让 $x=y=2$。这时 $x<y$ 和 $y<x$ 同时为假，全可比性无法通过。这个检查看出了重复元素带来的实际约束。

## 16 | 查找为什么返回 Option Nat

在 $[7,4,9]$ 里找 $4$，答案是下标 $1$。在同一个列表里找 $6$，没有可交回的合法下标。若用数字 $0$ 表示失败，便无法区别“没找到”和“在第一项找到”。`Option Nat` 提供两种构造：`none` 表示空缺，`some i` 保存一个自然数下标 $i$。

```lean
def linearSearch (key : Nat) : List Nat → Option Nat
  | [] => none
  | x :: xs =>
    if x = key then some 0 else (linearSearch key xs).map Nat.succ
```

### 为什么尾部的答案要加一

从 $[7,4,9]$ 的表头开始，$7\ne4$，任务交给 $[4,9]$。在尾部看来，$4$ 就在位置 $0$，所以返回 `some 0`。回到原来的列表，它前面多了一个 $7$，下标要加一，得到 `some 1`。这里的 $1$ 是位置，目标值仍然是 $4$。

`Nat.succ` 把 $j$ 变成 $j+1$。`map` 把这个操作伸进 `Option` 的包装里。如果尾部给出 `some j`，那么整体得到 `some (j+1)`；如果尾部给出 `none`，加一操作没有对象，整体仍是 `none`。

### 对两种返回值各问一句

$$

\begin{aligned}
\mathrm{search}(k,L)=\mathrm{none}
   &\iff k\notin L,\\
\mathrm{search}(k,L)=\mathrm{some}(i)
   &\implies L[i]?=\mathrm{some}(k).
\end{aligned}

$$

`xs[i]?` 是可失败的下标访问，越界时同样返回 `none`。第二式因此同时说明返回的位置存在，那里存放的确实是目标值。接下来两节分别证明这两句话。

> 先推算 `linearSearch 9 [7,4,9]` 的返回过程：最内层找到时是多少？回到上一层、再上一层各是多少？对 `linearSearch 8 [7,4,9]` 重做一次。

## 17 | 把“找不到”证明成双向等价

令 $F(L)$ 表示查找返回 `none`，令 $A(L)$ 表示目标值不在列表 $L$。我们要证明 $F(L)\leftrightarrow A(L)$。正向保证程序报告失败时列表里确实没有，反向保证列表里没有时程序会报告失败。

```lean
theorem linearSearch_none_iff (key : Nat) (xs : List Nat) :
    linearSearch key xs = none ↔ key ∉ xs := by
  induction xs with
  | nil => simp [linearSearch]
  | cons x xs ih =>
    by_cases hx : x = key
    · simp [linearSearch, hx]
    · simpa [linearSearch, hx, Ne.symm hx] using ih
```

### 空表、表头命中、表头失配

空表时，左边从定义化成 `none = none`，右边说明空列表没有成员，两边都成立。若表头等于目标值，函数返回 `some 0`，左边为假；目标就在表头，右边也为假。这里要证明的是等价关系，两边都为假时，这个等价关系为真。

若表头失配，剩下的目标读作：

$$

\underbrace{\text{尾部结果经下标加一后仍为空}}_{\iff F(xs)}
\ \longleftrightarrow\
\underbrace{\text{目标既不是表头，也不在尾部}}_{\iff A(xs)}.

$$

左边用上一节的 `map` 两条计算规则。右边用“属于 $x::xs$ 等价于等于 $x$ 或属于 `xs`”以及 $x\ne key$。因此要交出的命题正是已有的 `ih`。

### 最后一行浓缩了哪些依据

`simpa [...] using ih` 会按给定规则化简眼下的目标和已有事实，再检查它们能否对上。比较是 `x = key`，成员关系展开时也可能出现 `key = x`。`Ne.symm hx` 提供失配条件的反方向，避免这两个写法对不上。

> 在纸上对 $[]$、$[4]$、$[7,4]$ 分别判断等价式的左右两边。会有一组“两边都假”；尝试说出为什么它仍然通过定理的检查。

## 18 | 返回的下标为什么一定正确

假设 `found : linearSearch key xs = some i`。目标是 `xs[i]? = some key`。我们手里已经有“程序给了下标”的前提，要用它排除不可能的执行路径。分支越多，越值得先写一张表。

| 输入与比较 | 程序输出 | 从 found 得到什么 |
| --- | --- | --- |
| 空列表 | `none` | 与 `some i` 冲突，此支不可能。 |
| 表头命中 | `some 0` | 必有 $i=0$；下标 $0$ 处就是目标值。 |
| 表头失配，尾部失败 | `none` | 又与 found 冲突。 |
| 表头失配，尾部命中 $j$ | `some (j+1)` | $i=j+1$，用尾部位置 $j$ 的归纳假设。 |

### 在最难的一支中追到底

`cases ht : linearSearch key xs with` 拆开尾部的返回值，并把它的取值记录在等式 `ht` 中。假设尾部返回 `some j`。将 `ht` 和失配条件代入 `found`，已知 `some (j+1) = some i`，于是 $j+1=i$。源码里的 `simp [...] at found` 把这些计算用在已知条件上，`subst i` 随后在相关表达式中替换 $i$。

此时整个列表是 $x::xs$。读取它的第 $j+1$ 项，按定义就是读尾部 `xs` 的第 $j$ 项。对尾部使用 `ih j ht`，已得 `xs[j]? = some key`，正是所需。

### 用具体数字检验一次位置换算

在 $[7,4,9]$ 找 $4$ 时，这个分支中 $x=7$，尾部为 $[4,9]$，$j=0$。尾部的第 $0$ 项是 $4$，因此整个列表的第 $1$ 项也是 $4$。若忘了给尾部返回值加一，函数会声称下标 $0$ 处是 $4$，实际那里是 $7$。这条反例能准确定位程序应修改的地方。

> 两个查找定理合起来保证命中与缺失都可信。若还要单独证明“返回重复值的最小下标”，规格还需加入所有更小位置均不匹配的条件。

## 20 | 前三题的可运行证明

### 1　让目标决定取哪一个投影

```lean
example (P Q R : Prop) (h : (P ∧ Q) ∧ R) : R ∧ Q := by
  constructor
  · exact h.right
  · exact h.left.right
```

第一项目标是 $R$，位于外层右侧。第二项目标是 $Q$，先从外层向左取出 $P\wedge Q$，再向右取出 $Q$。若把两个分支的答案交换，第一处就会出现类型不匹配。

### 2　改写已知条件

```lean
example (a b : Nat) (h : a = b) (ha : a + 1 = 9) :
    b + 1 = 9 := by
  rw [h] at ha
  exact ha
```

`at ha` 选定已知条件作为重写位置。$a+1=9$ 变成 $b+1=9$，因此现在的 `ha` 与目标相同。另一种写法是在目标中用 `rw [← h]`，再使用原来的 `ha`。

### 3　复用引理，或者重新归纳

把[第 19 节](#unit-19)的 `countItems` 和[第 7 节](#unit-7)的 `appendNil` 放在同一命名空间后，第一种证明只需 `rw [appendNil xs]`，它把函数的输入替换为 `xs`。第二种写成：

```lean
example (xs : List Nat) : countItems (xs ++ []) = countItems xs := by
  induction xs with
  | nil => rfl
  | cons x rest ih =>
    change countItems (rest ++ []) + 1 = countItems rest + 1
    rw [ih]
```

这里先用定义把“数一个非空表”展开成“数尾部再加一”。$+1$ 在两边都保留，归纳假设替换的是内部的计数。比较[第 7 节](#unit-7)的证明：那里两边相同的是表头，这里两边相同的是加一操作。

## 21 | 后三题与独立读证明的方法

### 4　初值要能跟着程序一起改变

从 `sumFrom 0 [-3,5]` 开始，下一次是 `sumFrom (-3) [5]`，再下一次是 `sumFrom 2 []`。第一步推理需要把适用于尾部 $[5]$ 的归纳假设用在初值 $-3$ 上。若只知道 `sumFrom 0 [5] = [5].sum` 的数学内容，等式左侧不能与当前调用匹配。把初值推广后，$-3+5=2$，随后空表直接返回 $2$。

### 5　把来历与顺序分别核对

先保留 $1$，对 $[3,4]$ 递归插入 $3$。$3\le3$ 成立，于是新尾部变成 $[3,3,4]$，最终结果是 $[1,3,3,4]$。一次插入的排列引理保证新尾部成员要么是新插入的 $3$，要么来自旧尾部 $[3,4]$。第一种用 $1\le3$；第二种用旧列的有序性。值相同可能同时满足两种描述，这不会妨碍分情况证明。

### 6　把错误放进能发现它的规格

按题设，程序恰在目标缺失时返回 `none`，所以通过缺失规格。取列表 $[7,4]$ 和目标 $4$。它返回 `some 0`，而 $[7,4][0]$ 是 $7$。在长度为零或一的列表中，若找到目标，唯一可行的位置就是 $0$，因此长度二已经是最短反例。

### 下一次打开一个陌生定理

先把定理翻成“任给哪些对象、另需哪些假设、最终保证什么”。给它挑一个最小的正例和一个能暴露缺失条件的反例。随后对着源码只读当前一行：这一行引用的证明来自哪里？它的结论是否与当前目标对得上？遇到递归或归纳，多问一句“哪个参数真的变小了，哪个参数下次会改变”。

## 23 | 把最后一次进位也写下来

在纸上写 $1101_2+0111_2$。先盖住最左边三列，只看个位的 $1+1$。这一列应写 $0$，再把一个 $1$ 送到下一列。现在逐列填写表格；表中的行序就是程序读取输入的顺序。

| 位 $i$ | $a_i$ | $b_i$ | 传入 $c$ | 合计 | 写下 $s_i$ | 传出 $c'$ |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 1 | 1 | 0 | 2 | 0 | 1 |
| 1 | 0 | 1 | 1 | 2 | 0 | 1 |
| 2 | 1 | 1 | 1 | 3 | 1 | 1 |
| 3 | 1 | 0 | 1 | 2 | 0 | 1 |

程序先得到低位在前的 $[0,0,1,0]$。此时手里还有进位 $1$，附在末尾，结果是 $[0,0,1,0,1]$。按通常的高位在前写成 $10100_2=20$，等于 $13+7$。若把空输入分支写成空列表，最后的十六就会丢掉。

### 把一行表变成一个定理

```lean
def bitSum (a b c : Bool) := xor (xor a b) c
```

```lean
def carry (a b c : Bool) := (a && b) || (a && c) || (b && c)
```

```lean
theorem column (a b c : Bool) :
    (bitSum a b c).toNat + 2 * (carry a b c).toNat = a.toNat + b.toNat + c.toNat := by
  cases a <;> cases b <;> cases c <;> decide
```

`Bool` 只有两个值，对应位 $0,1$。`bitSum` 用三位异或取奇偶性，`carry` 检查三位中是否至少有两位为真。上面等号左边把传出的进位乘二，它将在高一位起作用。三个 `cases` 形成 $2^3=8$ 个分支；`<;>` 把后面的策略用于每一支。每支都只剩具体数的等式，由 `decide` 检查。

> 自己填 $1+0+1$ 和 $1+1+1$ 两行。两行都进位，留下的低位为什么不同？

## 24 | 从一列的等式拼出整串的等式

把第一行划掉。原来尚未计算的两段对应 $110_2$ 和 $011_2$，进入尾部的进位是 $1$。它们合起来是 $6+3+1=10$；乘二再加刚写的低位 $0$，得到 $20$。归纳步就是把这个算式里的具体数换成任意尾部。

```lean
def addBits : List (Bool × Bool) → Bool → List Bool
  | [], c => [c]
  | (a,b) :: xs, c => bitSum a b c :: addBits xs (carry a b c)
```

输入是成对的位列，因此两个数的位宽天然相同。`value` 对空列表取零，对表头 $a$ 和尾部 $A$ 取 $a+2\,\mathrm{value}(A)$。若把函数限制在初始进位 $0$，第一次递归很可能就用不上归纳假设，所以正确性定理允许任意进位 $c$。

```lean
theorem addBits_correct (xs : List (Bool × Bool)) (c : Bool) :
    value (addBits xs c) = value (xs.map Prod.fst) + value (xs.map Prod.snd) + c.toNat := by
  induction xs generalizing c with
  | nil => simp [addBits, value]
  | cons p xs ih =>
    obtain ⟨a,b⟩ := p
    simp only [List.map_cons, addBits, value, ih]
    have h := column a b c
    omega
```

`generalizing c` 保留任选进位的权利。空表时返回单独的 $c$。非空时 `obtain` 拆开这一列的两个输入位；`map Prod.fst`、`map Prod.snd` 分别读每列的第一、第二分量。`simp only` 依次展开表头和赋值规则，再把下一层的结果按归纳假设替换。写 $A,B$ 为两条尾部的值，剩余等式是

$$

 s+2(A+B+c')=(a+2A)+(b+2B)+c .

$$

`have h` 提供 $s+2c'=a+b+c$，`omega` 整理整数系数，把左右两式对齐。独立的 `addBits_width` 对每多一列就在输出前多放一位，基例输出一位，所以恰好输出 $n+1$ 位，即使最高进位是零也保留它。

## 25 | 给三次函数找到两道界

取 $n=10$，原函数四项分别为 $1,10000,-1000,3$，和为 $9004$。这时候二次项远大于三次项。要回答增长阶，应找到从某处起始终成立的上下界，不能只看这个输入。

### 把分母先移走

令 $F(n)=1000 f(n)=n^3+100000n^2-100000n+3000$。固定 $n\ge1$。因为 $n^2-n\ge0$，所以 $F(n)\ge n^3$。求上界时丢掉负项，再用 $n^2\le n^3$ 和 $1\le n^3$，得到 $F(n)\le103001n^3$。两边除以正数 $1000$，便给出了 $\Theta(n^3)$ 所需的两个正常数及起点 $n_0=1$。

```lean
theorem cubic (n : Int) (hn : 1 ≤ n) :
    n^3 ≤ scaled n ∧ scaled n ≤ 103001*n^3 := by
  have h₂ : n ≤ n^2 := by
    simpa [Int.pow_succ] using Int.mul_le_mul_of_nonneg_left hn (show 0 ≤ n by omega)
  have h₃ : n^2 ≤ n^3 := by
    simpa only [Int.mul_one, Int.pow_succ n 2] using Int.mul_le_mul_of_nonneg_left hn (show 0 ≤ n^2 by omega)
  unfold scaled
  omega
```

`Int` 允许直接处理减号。两条 `have` 分别给出 $n\le n^2$ 与 $n^2\le n^3$。它们都从 $1\le n$ 出发，同乘非负的 $n$ 或 $n^2$；`simpa` 把结果写成幂。`unfold` 替换 $F$ 的定义。最后 `omega` 把已经建立的幂之间的不等式相加，此时不用它猜测乘法的单调性。

> 上界系数可以很松。若只证明 $f(n)\le Cn^3$，还缺哪一半？例如 $n^2$ 同样满足这句上界。

## 26 | 选择排序每一轮固定哪个位置

用 $[4,2,1,3]$ 手算。第一轮扫描四项找出 $1$，与首项 $4$ 交换，成为 $[1\mid 2,4,3]$。第二轮最小值 $2$ 就在待处理部分的首位，得到 $[1,2\mid 4,3]$。第三轮交换 $4,3$。只剩一个数时，没有任何次序需要再决定。

### 写成循环

```text
for i = 1 .. n-1
  j = i
  for t = i+1 .. n
    if A[t] < A[j] then j = t
  swap A[i], A[j]
```

内层每看完一个位置，$j$ 指向已扫描范围中的一个最小值。外层第 $i$ 轮前，前 $i-1$ 项有序，且其中每项不大于剩余的任一项；整个数组仍是输入的排列。开始时前缀为空。选出最小值并交换后，旧前缀可以安全地接上它，余下的每项仍不小于它。交换保留元素的次数。这三件事一起解释了停止时的完整规格。

```lean
def select : Pass := fun a xs =>
  let m := (a::xs).min (by simp)
  if m = a then (a,xs) else (m,replaceFirst m a xs)
```

`a` 是首项，`xs` 是它后面的部分。非空列表可取 `min`。若最小值已在首位，原样返回；否则把右侧第一次出现的最小值换成旧首项，再把最小值放到首位。比如第一轮是把尾部 $[2,1,3]$ 改为 $[2,4,3]$。这正是数组交换在列表上的效果，重复最小值也只换一个。

## 27 | 选择排序的证据与比较次数

试着先排序 $[1,2,3,4]$。第一轮仍要拿首项与三项比较，后两轮各比较两次、一次。换成 $[4,3,2,1]$，交换变多，找最小值仍花 $3+2+1=6$ 次比较。

### Lean 如何拼接一次选择的证明

```lean
  intro a xs
  let m := (a::xs).min (by simp)
  have hm : (a::xs).min? = some m := List.min?_eq_some_min (by simp)
  obtain ⟨hmIn, low⟩ := List.min?_eq_some_iff.mp hm
```

`hm` 把最小值函数的可选结果与这里的 $m$ 对接。`obtain` 从库定理取出两份事实：$m$ 确实出现过；它小于等于旧列表的每个元素。接下来 `by_cases eq : m=a` 分两支。相等时排列用自反性；不等时由 $m$ 属于整列推出它属于尾部，用 `exchange` 证明交换前后为排列。最后通过排列的 `mem_iff` 把新尾部的成员送回旧列，再应用最小值的下界。

通用定理 `rounds_ok` 只向每轮索取“保持排列”和“选出的表头不大于新尾部”。令轮数 $k=n-1$。证明对 $k$ 归纳；$k=0$ 时条件 $n\le k+1$ 表明最多只剩一项。递推时，一轮排列的长度等式保证尾部恰好短一项，把归纳假设用于尾部，最后在它前面接上最小值。

### 从六次比较推广到任意长度

在 `BinaryAndCosts.lean` 中，`tri 0 = 0`，`tri (n+1) = tri n + n`。对 $n$ 归纳得 $2\,\mathrm{tri}(n)+n=n^2$。归纳步只需把左侧改写成 $2\mathrm{tri}(n)+2n+n+1$，再使用旧等式。于是比较总数是 $n(n-1)/2$。当 $n\ge2$ 时它介于 $n^2/4$ 和 $n^2/2$ 之间，最好、最坏均为 $\Theta(n^2)$。

## 28 | 线性查找平均要看几项

纸上放四张不同的牌 $[8,3,6,2]$。抽到哪一个值，就从左边开始找它。四个目标等可能，查找次数分别是 $1,2,3,4$，总数 $10$，平均 $10/4=2.5$。这个小数是很多次查找的平均，一次具体查找永远只检查整数项。

```lean
def totalProbes : Nat → Nat
  | 0 => 0
  | n+1 => totalProbes n + (n+1)
```

```lean
theorem successful_sum (n : Nat) : 2 * totalProbes n = n*(n+1) := by
  induction n with
  | zero => rfl
  | succ n ih => simp only [totalProbes]; grind
```

`totalProbes` 累加所有可能命中位置的代价，而非在一次查找里走遍所有位置。列表多一项，新增的那种成功查找恰好花 $n+1$ 次。证明不在自然数里做会截断的小数除法，先证明 $2S(n)=n(n+1)$。`induction` 给出旧总数的等式，`simp only` 展开一次递推，`grind` 展开乘积，用旧等式消去 $2S(n)$。

### 最后再取平均

在 $n>0$、目标的唯一命中位置均匀分布时，平均为 $S(n)/n=(n+1)/2$。它夹在 $n/2$ 与 $n$ 之间，所以平均为 $\Theta(n)$。把目标放到最后一项，恰好检查 $n$ 次；任何输入至多检查 $n$ 次，最坏也为 $\Theta(n)$。

> 若允许查找失败，失败时要扫完整表；若有重复值，程序可能在抽到的位置之前就已命中。先说清概率模型，才能决定上述平均式是否适用。

## 29 | 给排序加上有序输入的快速返回

检查 $[2,2,5,8]$。依次比较相邻的 $2\le2$、$2\le5$、$5\le8$，全部通过，可直接交回输入。改成 $[2,5,2,8]$，第二次就看见 $5>2$，此时改走原来的排序程序。

```lean
def ordered : List Nat → Bool
  | a :: b :: xs => decide (a ≤ b) && ordered (b :: xs)
  | _ => true
```

```lean
  unfold guarded
  split
  next h => exact ⟨(ordered_spec xs).mp h, .refl _⟩
  next => exact ok xs
```

前一段递归只把窗口向右移一项。`&&` 要求当前相邻对通过且剩余部分也通过，长度为零或一时直接通过。证明 `ordered_spec` 的递推步要解释“相邻有序怎样推出整列有序”：从 $a\le b$ 和 $b$ 小于等于尾部每个 $z$，用传递性得到 $a\le z$。反向则从整列有序取出相邻对，再取出尾部有序。

后一段是包装函数的证明体。`unfold` 展开预检，`split` 按检查结果分支。成功分支用 `ordered_spec` 取得有序证据，用 `.refl` 证明输入是自己的排列；失败分支把输入交给原排序的规格 `ok`。因此提前返回保留了原来的正确性。

### 最好情形花多少

有序输入上恰做 $n-1$ 次相邻比较，按单位代价为 $\Theta(n)$。在比较排序模型下，即便输入已经有序，也要获得足够证据：若 $n$ 个不同元素之间的比较图仍不连通，就不能排除某个分量的值整体落到另一个分量的另一侧。连通至少需要 $n-1$ 条边。预检因此达到了线性最好时间。

$$

\begin{aligned}
 &[3,41,52,26]\mid[38,57,9,49]\\
 &[3,41]\mid[52,26]\mid[38,57]\mid[9,49]\\
 &[3]\mid[41]\mid[52]\mid[26]\mid[38]\mid[57]\mid[9]\mid[49]\\
 &\longrightarrow [3,41]\mid[26,52]\mid[38,57]\mid[9,49]\\

\end{aligned}

$$

最后一轮先比 $3,9$，取 $3$；再比 $26,9$，取 $9$；随后从 $26,38$ 取 $26$，从 $41,38$ 取 $38$。依次取 $41,49,52$ 后，左队为空，直接接上 $57$。

## 31 | 递归会不会制造空区间

取闭区间 $[3,7]$。中点取整为 $5$，两个子区间是 $[3,5]$ 与 $[6,7]$，都非空。再试最窄的可分区间 $[6,7]$：中点是 $6$，两边各剩一个元素。此时两个端点相等，停止递归。

```lean
theorem split_bounds (p r : Nat) (h : p < r) :
    p ≤ (p+r)/2 ∧ (p+r)/2 < r ∧ (p+r)/2-p < r-p ∧ r-((p+r)/2+1) < r-p := by omega
```

开始时若 $n\ge1$，根区间 $[1,n]$ 满足左端点不大于右端点。假设某次调用也满足 $p\le r$，且通过了测试 $p\ne r$，两条信息合起来就是 $p<r$。令 $q=\lfloor(p+r)/2\rfloor$。从 $2p\le p+r<2r$ 得 $p\le q<r$，因此 $q+1\le r$。这恰是下两次调用各自非空的条件。

`split_bounds` 的前两项刻画中点位置，后两项说明左右子问题的宽度都严格小于 $r-p$。`omega` 在这些自然数等式中处理除以常数二的取整和自然数减法。程序从根往下，每经过一条边就重新得到非空条件，而宽度不能无限次严格下降。由此可把停止测试写成 $p=r$。

> 如果初次调用给的是 $[1,0]$，归纳的起点就没成立。能接受空输入的实现通常保留 $p<r$ 才递归的写法。

## 32 | 归并循环里，已经写下的前缀是什么

把两叠有序牌 $L=[2,6,7]$、$R=[1,2,5]$ 放在两边。先取右侧的 $1$，再遇到左右同为 $2$，按左侧优先取左边的 $2$。此时输出 $O=[1,2]$，左边还剩 $[6,7]$，右边还剩 $[2,5]$。这时已消耗的两边项数 $1+1$，恰等于已写项数 $2$。

### 写成一个能从头保持到尾的等式

固定完整结果 $M=\mathrm{merge}(L_0,R_0)$。每一轮开始时，$O$ 是已经消耗掉的两段合成的有序前缀，且

$$

 O\mathbin{++}\mathrm{merge}(L,R)=M .

$$

因为两段输入原本有序，$M$ 有序且是原输入拼接的排列，故 $O$ 正好包含应输出的最小的 $|O|$ 项。初始时 $O=[]$，两队均未消耗，等式直接成立。

```lean
theorem left_step (out l r : List Nat) (a b : Nat) (h : a ≤ b) :
    out ++ merge (a::l) (b::r) = (out ++ [a]) ++ merge l (b::r) := by
  simp [merge, h, List.append_assoc]
```

`h` 表明左队首 $a$ 应当先输出。`simp` 按这个比较展开一次归并，在左式里得到 $O\mathbin{++}(a::\mathrm{merge}(l,b::r))$。结合律把它写成先将 $a$ 接到 $O$ 末尾再归并余项。这就是拿走左牌后的新不变量。`right_step` 证明右侧更小时的同一句话；相等落在左分支。

### 主循环退出后为什么还要复制

样例接下来从右侧取 $2,5$，右队空了。剩下的 $[6,7]$ 仍属于最终结果。此时 $\mathrm{merge}(L,[])=L$，逐个抄完相当于整段接到 $O$ 后。若左队先空，道理对称。`merge_ok` 用 `constructor` 分开有序和排列；库引理 `pairwise_merge` 使用比较关系的传递性和全可比性以及两边有序，`merge_perm_append` 则说明没有丢失、复制任何元素。

## 33 | 用高度写清归并递推的基例

题给最小规模是 $2$。依次算 $T(2)=2$，$T(4)=2\cdot2+4=8$，$T(8)=2\cdot8+8=24$。分别除以 $2,4,8$，得到 $1,2,3$，恰好是这些数的以二为底的对数。

```lean
def mergeCost : Nat → Nat
  | 0 => 2
  | h+1 => 2 * mergeCost h + 2^(h+2)
```

```lean
theorem mergeCost_exact (h : Nat) : mergeCost h = 2^(h+1)*(h+1) := by
  induction h with
  | zero => rfl
  | succ h ih => simp only [mergeCost, ih, Nat.pow_succ]; grind
```

参数 $h$ 数的是从规模 $2$ 再翻倍几次，所以实际规模是 $n=2^{h+1}$。例如前面算的 $T(8)$ 对应 `mergeCost 2`。这么选参数，使 Lean 的自然数归纳从零开始，却仍对应题目的基例。

设结论在 $h$ 成立。记 $s=2^{h+1}$，下一层规模 $2s$。把递推左边算一下：

$$

 T(2s)=2T(s)+2s=2s(h+1)+2s=2s(h+2).

$$

```lean
def insertRev (x : Nat) : List Nat → List Nat
  | [] => [x]
  | y::ys => if x<y then y::insertRev x ys else x::y::ys
```

```lean
def recursiveSortRev : List Nat → List Nat
  | [] => []
  | x::previous => insertRev x (recursiveSortRev previous)
```

`previous` 表示原输入去掉末项后的逆序。`recursiveSortRev previous` 完成较短问题，再调用 `insertRev`。若 $x<y$，旧值 $y$ 需要右移，逆序表示中保留 $y$ 为表头，继续处理尾部。否则 $x$ 可以放在这里。`prefix_ok` 用归纳分别证明排列和降序，递推时调用 `insert_perm`、`insert_desc`，因此转回正序后保持了输入元素并按升序排列。

对原输入 $[4,3,2,1]$，依次插入时分别搬移 $1,2,3$ 项。一般地，$T(1)=\Theta(1)$，$T(n)=T(n-1)+\Theta(n)$，逆序输入能在每层达到这项线性代价。展开得到 $\Theta(n^2)$；只数搬移则恰为 `tri n`。后面的 `shift_count` 将单次搬移数精确对应到比新值大的旧元素个数。

```lean
def binary (a : Nat → Int) (key : Int) : Nat → Nat → Nat → Option Nat
  | 0, _, _ => none
  | fuel+1, lo, w =>
    if w = 0 then none else
    let m := lo + w/2
    if a m = key then some m
    else if key < a m then binary a key fuel lo (w/2)
    else binary a key fuel (m+1) (w-w/2-1)
```

## 36 | 把找到、没找到和最坏时间都说清楚

回看上一节第一次比较。丢掉的下标 $0,1,2,3$ 上的数全都不超过 $11$。如果递归最后说保留的右半边也没有 $14$，那么可以把这两份“没有”合在一起。证明失败分支时，这一小步尤其容易被略去。

```lean
def Answer (a : Nat → Int) (key : Int) (lo w : Nat) : Option Nat → Prop
  | none => ∀ i, lo ≤ i → i < lo+w → a i ≠ key
  | some i => lo ≤ i ∧ i < lo+w ∧ a i = key
```

`binary_ok` 对 `fuel` 做归纳，同时允许下标和宽度改变。假设 `w < 2^fuel` 且区间有序。额度为零意味着 $w<1$，因此不存在区间内的 $i$。额度充足且命中时，直接提供三项证据：$m$ 在左端之后、结束点之前、值等于目标。

若目标小于中点值，证明把归纳假设应用于左半边；旧条件 $w<2^{f+1}$ 推出 $\lfloor w/2\rfloor<2^f$，子区间仍有序。若返回 `some j`，把下标范围放宽到原区间即可。若返回 `none`，对任一旧下标分情况：在左侧用归纳结论；在中点或其右侧，用有序性得到 $a_i\ge a_m>key$。向右递归的证明交换两侧，并利用中点已经排除相等。

### 为什么是紧确的对数界

`probes` 在每次非空比较处加一。`probe_upper` 对额度归纳，每支最多再花 $f$ 次。要有匹配的下界，取全零的有序数组，搜索 $-1$，每次都进入宽度恰为 $\lfloor w/2\rfloor$ 的左侧。`probe_lower` 展开该分支，对 $w=1$ 单独结算；在 $w\ge2$ 时用 $\lfloor\lg w\rfloor=1+\lfloor\lg\lfloor w/2\rfloor\rfloor$。于是非空输入的最坏探测数恰为 $\lfloor\lg n\rfloor+1$，在常数时间随机访问模型下为 $\Theta(\lg n)$。

## 37 | 左半边查找失败之后

找 $5$，当前区间的值为 $[2,4,7,9]$。中点值 $7$ 比目标大，递归去左半边 $[2,4]$，结果为 `none`。现在假设有人指出一个位置 $i$，说那里藏着 $5$。如何反驳，取决于 $i$ 在中点的哪一侧。

```lean
have h := ih lo (w/2) (by omega)
  (fun i j hi hij hj => hs i j hi hij (by omega))
cases e : binary a key f lo (w/2) with
| some j => rw [e] at h; exact ⟨h.1, by have := h.2.1; omega, h.2.2⟩
| none =>
  rw [e] at h
  intro i hi stop
  by_cases side : i < lo+w/2
  · exact h i hi side
  · have := hs (lo+w/2) i (by omega) (by omega) stop
    omega
```

命中分支把原有的位置下界和命中等式保留，只把区间上界放宽。第一条 `have` 取得子区间答案的规格。它需要两个条件：左子区间的宽度装得进剩余额度，且左子区间有序。`fun i j ...` 表示任取子区间的两个下标，它们也落在旧区间，故原来的 `hs` 可直接回答。

```lean

  (List.range n).any fun i => (binary a (x-a i) (n.log2+1) (i+1) (n-i-1)).isSome
```

```lean
def solve (xs : List Int) (x : Int) :=
  let ys := xs.mergeSort
  let arr := ys.toArray
  twoSum (fun i => arr[i]?.getD 0) arr.size x
```

外层 `List.range n` 提供 $0$ 至 $n-1$ 的下标。`any` 表示只需一项成功就返回真。固定 $i$，二分的起点是 $i+1$，宽度是 $n-i-1$，两个下标一定不同。`.isSome` 把“找到某个位置”转换为布尔真。`solve` 先归并排序，把结果一次转为数组，再让查询重复使用同一个数组。

### 时间从哪里来

排序花 $\Theta(n\lg n)$ 最坏时间。转数组花 $\Theta(n)$；最多 $n$ 次查询，每次 $O(\lg n)$。先排序再查，最坏总时间为 $\Theta(n\lg n)$。即使提前找到一对，也已经付过这次排序的费用。

```lean

  | 0 => 0
  | h+1 => mergeLevels n h + n
```

```lean
    | nil => simp [rounds]
    | cons a xs =>
      obtain ⟨m,ys,e⟩ : ∃ m ys, pass a xs = (m,ys) := ⟨_,_,rfl⟩
      have h := valid a xs
      rw [e] at h
      obtain ⟨hp,lo⟩ := h
      have len := hp.length_eq
      obtain ⟨hs,perm⟩ := ih ys (by simp at len enough; omega)
      simp only [rounds,e,List.pairwise_cons]
      exact ⟨⟨fun z hz => lo z (perm.mem_iff.mp hz),hs⟩,(perm.cons m).trans hp⟩
```

`rounds_ok` 是选择排序和冒泡排序共用的外层证明。这段非空分支先给 `pass a xs` 的两个返回值命名，并用 `rw [e]` 把每趟规格 `valid` 写成关于 $m$ 和 `ys` 的命题。`hp.length_eq` 由排列得到长度相等，消去各一项后即知 `ys` 够短，可以调用 `ih`。尾部排序后若 $z$ 属于结果，`perm.mem_iff` 把它送回 `ys`，此时 `lo` 仍然能证明 $m\le z$。最后把尾部排列两边加上 $m$，与本趟排列接起来。

### (d) 时间

长度为 $n$ 的待排段内层总做 $n-1$ 次相邻比较。下一趟少一次，共计 $n(n-1)/2$。题给程序没有提前退出，因此即使每次都不交换，仍有这么多次比较。最坏与插入排序同为 $\Theta(n^2)$；有序输入上直接插入排序只需线性时间。

## 45 | 把多项式折起来，少算多少次

取 $P(x)=3-x+2x^2+4x^3$、$x=2$。直接算得 $3-2+8+32=41$。再从最高次系数向下算，用一个变量 $p$：开始为 $0$，读 $4$ 得 $4+2\cdot0=4$；读 $2$ 得 $10$；读 $-1$ 得 $19$；读 $3$ 得 $41$。只需保存上一行的一个数。

```lean
def horner (x : Int) : List Int → Int
  | [] => 0
  | a::as => a + x * horner x as
```

系数列表把常数项放在表头。先求尾部的值再执行 $a+xp$，展开后恰按刚才的顺序从高次向低次计算。(a) 有 $m=n+1$ 个系数，原循环每项一次乘、一次加；以算术操作为单位，时间是 $\Theta(n+1)$，随次数增长即 $\Theta(n)$。

### (b) 每一项重新算幂

```text
sum = 0
for i = 0 .. n
  power = 1
  repeat i times: power = power * x
  sum = sum + a[i] * power
```

样例重算四个幂的乘法数依次为 $0,1,2,3$，再乘四次系数，共 $10$ 次。这里特意使用逐次乘法。`mulPower` 的零次幂为一，后继次数多乘一次；`power_ok` 用归纳和幂的递推式证明它等于 $x^k$。

```lean
theorem naive_work (m : Nat) : 2 * naiveMultiplications m = m*(m+1) := by
  induction m with
  | zero => rfl
  | succ m ih => simp only [naiveMultiplications]; grind
```

在原有 $m$ 个系数后加上第 $m$ 次项，额外做 $m+1$ 次乘法。展开 `naiveMultiplications` 的一层，用归纳假设合并旧费用，得 $2C(m)=m(m+1)$。朴素实现的乘法数为 $\Theta(n^2)$，而 Horner 利用相邻幂之间的关系把运算数降到线性。

## 46 | 为什么中间值恰好是一个后缀多项式

还是 $x=2$。读完 $a_3=4,a_2=2$，手里是 $p=10$。它表示 $a_2+a_3x$；乘回 $x^2$ 就得到原多项式的高次部分 $2x^2+4x^3=40$。接下来把 $-1$ 接到低次端，得到 $-1+2\cdot10=19$。这个算例提示我们应当如何重排每一项的指数。

### 写出循环不变量

准备处理第 $i$ 项时，$p=\sum_{j=i+1}^{n}a_jx^{j-i-1}$。初始化时 $i=n$，空和为零。更新 $a_i+xp$ 将已处理部分的指数全提高一位，再添上 $a_i$，于是恰好得到下一轮所需的和。完成 $i=0$ 后，手里的就是原多项式。

```lean
def powersFrom (x : Int) (k : Nat) : List Int → Int
  | [] => 0
  | a::as => a*x^k + powersFrom x (k+1) as
```

```lean
theorem suffix (x : Int) (k : Nat) (as : List Int) :
    powersFrom x k as = x^k * horner x as := by
  induction as generalizing k with
  | nil => simp [powersFrom,horner]
  | cons a as ih =>
    rw [powersFrom,horner,ih (k+1),Int.pow_succ]
    grind
```

`powersFrom x k as` 保留原指数 $k,k+1,\dots$；`horner x as` 则把这个后缀的最低次数重新看作零。`suffix` 证明前者等于 $x^k$ 乘后者。空表两侧均为零。递推时先展开一个系数 $a$，把归纳假设用在 $k+1$；`Int.pow_succ` 将 $x^{k+1}$ 写成 $x^kx$。最后的 `grind` 用分配律及乘法交换律核对

$$

 a x^k + (x^kx)H=x^k(a+xH).

$$

取 $k=0$ 得 `horner_correct`。系数可以为负，$x$ 也可以为零；推导只用了整数加乘，没有除以 $x$。

## 47 | 逆序数是在数哪些位置对

对题给 $[2,3,8,6,1]$ 从左到右做标记。$2$ 右侧较小的只有 $1$，$3$ 也只有 $1$；$8$ 右侧有 $6,1$；$6$ 右侧有 $1$。这样每对只按左端点数一次。(a) 一基下标的五对是 $(1,5),(2,5),(3,4),(3,5),(4,5)$，总数 $1+1+2+1+0=5$。

```lean
def inv : List Nat → Nat
  | [] => 0
  | x::xs => smaller x xs + inv xs
```

`smaller x xs` 数尾部严格小于 $x$ 的元素。递归把全部逆序分成两组：左端点是表头，或者两个端点都在尾部。这一实现适合写规格，直接按它执行可能要做二次数量级的检查。

### (b) 怎样达到最大值

在 $[5,4,3,2,1]$ 中，每一对不同位置都是逆序，共 $4+3+2+1=10$。任意排列最多也就有这么多对。一般地，$n$ 项最多 $n(n-1)/2$ 对，严格降序排列全部达到；若要每一对都逆序，相邻项也必须严格下降。

```lean
theorem max_bound (l : List Nat) : inv l ≤ pairs l.length := by
  induction l with
  | nil => decide
  | cons x xs ih => simpa [inv,pairs] using Nat.add_le_add (List.countP_le_length (p := fun y => decide (y<x))) ih
```

`List.countP_le_length` 给出表头的贡献至多为尾长，`Nat.add_le_add` 再接上尾部归纳界。`decreasing_max` 对递减的 $[n-1,\dots,0]$ 证明达到此界。加一个新的最大值 $n$ 在表头，尾部每项都满足“小于 $n$”，`countP_eq_length` 使计数成为整个尾长。全体数加一就对应题目的 $\{1,\dots,n\}$，不会改变任何比较。`pairs_exact` 把这个递推上界化为三角数。

## 48 | 插入排序的每次右移对应哪个逆序

按原顺序向前缀加入 $2,3,8,6,1$。加入 $6$ 时，旧前缀只有 $8$ 大于它，搬一次；加入 $1$ 时，旧前缀四项都比它大，搬四次。其他轮不搬，总计五次。这里换了统计方向：按照逆序对的右端点分组。

```lean
theorem append_one (l : List Nat) (x : Nat) : inv (l++[x]) = inv l + larger x l := by
  rw [inv_append,cross_right]
  simp [inv,smaller]
```

```lean
theorem shifts_are_inversions (rev : List Nat) : totalShifts rev = inv rev.reverse := by
  induction rev with
  | nil => rfl
  | cons x rev ih =>
    rw [totalShifts,List.reverse_cons,append_one,ih,shift_count x _ (prefix_ok rev).2]
    have perm := (prefix_ok rev).1.trans (List.reverse_perm (l := rev)).symm
    rw [larger,perm.countP_eq]
```

`append_one` 在旧列表的末尾加入 $x$。按区间拆开逆序后，唯一新增的就是旧列表中大于 $x$ 的项；单元素列表的内部逆序为零。`totalShifts` 用逆序存放的前缀运行插入。空表没有搬移；递推步用 `ih` 把历史搬移换成历史逆序，用 `shift_count` 把本轮搬移换成一次筛选计数。

为什么可以在排过序的旧前缀中数较大值？`prefix_ok` 表明该前缀仅仅换了次序；反转也保留排列。`countP_eq` 保证沿这个排列，满足“比 $x$ 大”的元素数不变。于是总搬移与原输入逆序数一一对应。

### 从精确搬移数得到运行时间

每轮还要读入新值、检查循环条件并把新值写回，所以即使没有逆序，也有线性启动和收尾开销。成功通过内层条件的次数正好是逆序数 $I$，每轮至多另加一次结束检查。故插入排序的时间为 $\Theta(n+I)$。有序时 $I=0$；逆序时 $I=n(n-1)/2$。这也解释了插入排序为什么适合接近有序的输入。

## 49 | 在一次归并里数完跨界逆序

把 $[2,3,8,6,1]$ 按本实现拆成 $[2,3]$ 和 $[8,6,1]$。左右内部逆序数为 $0$ 和 $3$。排好后的两队是 $[2,3]$ 与 $[1,6,8]$。右队首的 $1$ 先出队，直接记下左队尚余的两项 $2,3$；之后不再增加跨界计数。总数 $0+3+2=5$。

```lean
def scan (n : Nat) : List Nat → List Nat → Nat
  | [], _ => 0
  | _, [] => 0
  | x::xs, y::ys => if x ≤ y then scan (n-1) xs (y::ys) else n + scan n (x::xs) ys
```

参数 $n$ 缓存左队余长，避免每次从链表头重新数长度。若 $x\le y$，整个有序右队都不小于 $x$，它不贡献跨界逆序，消耗左牌并让 $n$ 减一。若 $x>y$，整个有序左队都大于 $y$，一次加入 $n$，只消耗右牌。队列之一为空时没有跨界对。相等时走左分支，保证只数严格大于。

### 关键等式怎样交给 Lean

定义 `cross l r` 为对每个左元素 $x$ 求右队中较小值的个数，再求和。`cross_right` 证明

$$

 C(L,y::R)=\#\{x\in L:x>y\}+C(L,R).

$$

证明对 $L$ 归纳，每多一个左表头，就只多问一次“它是否大于 $y$”。`scan_ok` 对两队长度递减做归纳。左出队时用 `countP_eq_zero` 证明这一项贡献为零；右出队时用 `countP_eq_length` 证明整队都贡献，再用 `cross_right` 和尾部归纳假设。这使线性扫描的返回值等于按所有跨界对定义的数。

## 50 | 把跨界计数接回整棵归并树

再试 $[3,1\mid4,2]$。左半内部一对，右半内部一对。按两边排好后的 $[1,3]$ 与 $[2,4]$ 找到跨界的 $(3,2)$ 一对，总计三对。若只对最终排好的一整列去数，答案反而会是零。子问题必须同时交回“排好的值”和“原来有多少逆序”。

```lean
def counted : Nat → List Nat → List Nat × Nat
  | 0, xs => (xs,0)
  | k+1, xs =>
    if xs.length ≤ 1 then (xs,0) else
    let mid := xs.length / 2
    let (l,a) := counted k (xs.take mid)
    let (r,b) := counted k (xs.drop mid)
    (merge l r, a+b+scan mid l r)
```

`mid` 为左半长。两个 `let` 分别绑定一次递归返回的有序队列和计数。用 `merge` 得到父节点的有序输出，再把两个子计数和 `scan` 的跨界计数相加。此处为了便于分别验证，归并输出和跨界计数各做一次线性扫描；两次之和仍为线性。

### 把代码的三个返回性质对齐

`counted_ok` 的结论同时要求输出是原输入的排列、输出有序、计数等于 `inv xs`。当长度至多一时直接成立；归纳步 `take_append_drop` 证明两半接回恰为原输入。对左右各用一次归纳假设。随后 `merge_perm_append` 给出排列，`pairwise_merge` 给出有序性。对计数，用 `scan_ok` 换回跨界规格；用 `cross_perm` 说明两边各自重排不影响跨界数；最后 `inv_append` 把三类互不相交的位置对合回 `inv xs`。

在根调用 `counted xs.length xs` 给出足够递归额度；运行遇到单元素就提前返回。平衡折半后深度为 $\Theta(\lg n)$，每一层处理的长度总和为 $n$，含拆分、归并与计数，故最坏为 $\Theta(n\lg n)$。用前一节的二次规格核对了结果，不必实际枚举二次多个位置对。

## 51 | 一次批量计数的等式从哪儿来

取左列 $[3,5,7]$、右列 $[2,6]$。右首 $2$ 比左首 $3$ 小，它跟左边三项都构成逆序。删去 $2$ 后还有 $(7,6)$ 一对。应当证明的等式是 $4=3+1$。下面是 `scan_ok` 右出队分支使用的核心代码。

```lean
        simpa [cross,zero] using ih (y::ys) ht hr
      · have allLarge : larger y (x::xs) = (x::xs).length := List.countP_eq_length.mpr (by
          intro z hz
          rcases List.mem_cons.mp hz with rfl | hz
          · simp; omega
          · have := hx z hz; simp; omega)
        rw [scan,if_neg h,cross_right,allLarge,jr (List.pairwise_cons.mp hr).2]
```

`allLarge` 把“所有左队元素都大于右首”变成一个可用于加法的等式。`List.countP_eq_length.mpr` 把目标换成“任取左队成员 $z$，它都通过判定”。`List.mem_cons.mp` 将成员的来历分为表头和尾部；在第一支用失配条件推出 $y<x$，在第二支由 `hx z hz` 得 $x\le z$，所以同样有 $y<z$。

最后的 `rw` 顺着公式走四步：展开 `scan` 并选定右出队；按 `cross_right` 把规格中的右首贡献拆出来；代入 `allLarge`；用 `jr` 把余下扫描换成它的规格。`hr` 是右列有序的证明，其中第二部分给出右尾部有序，正好是这次归纳调用需要的条件。

### 从局部等式返回总数

```lean
      simpa using h
    · have hlen : L.length = mid := lp.length_eq.trans len
      rw [lc,rc,← hlen,scan_ok _ _ ls rs,cross_perm l L r R lp rp,← inv_append,cat]
```

`hlen` 把子函数返回的左列长度连回拆分点 `mid`。`lc` 和 `rc` 替换两个内部计数。`scan_ok` 需要两份有序证据 `ls,rs`。`cross_perm` 再把排好序的 $L,R$ 换成原左右段 $l,r$。逆用 `inv_append` 合并三部分，再用 `cat` 把拼回来的输入换为原列表。最终两边是同一个 `inv xs`。
